อกสารนี้อธิบายส่วนที่ใช้ในโปรเจกต์จริงแบบง่าย ๆ เพื่อให้ดูโค้ดแล้วเข้าใจว่าทำไมถึงเขียนแบบนี้

## 1. การหาระยะจาก GPS

ตอนอาจารย์เปิดรอบเช็กชื่อ ระบบจะเก็บ latitude และ longitude ของอาจารย์ไว้ก่อน พอนักศึกษากดเช็กชื่อก็ส่งพิกัดของตัวเองมา แล้วนำสองจุดมาเทียบกัน

ใน `src/attendance_service.py` ใช้สูตร Haversine เพราะพิกัด GPS เป็นพิกัดบนโลก ไม่ใช่ระยะบนแกน X/Y ธรรมดา

ค่าระยะที่คำนวณได้เป็นเมตร และในโปรเจกต์กำหนดไว้ว่าไม่เกิน 50 เมตรจึงจะผ่าน

## 2. การตรวจใบหน้าในโปรเจกต์นี้

โปรเจกต์นี้ยังไม่ได้ใช้โมเดลรู้จำใบหน้าจริง เพราะทำเป็นต้นแบบสำหรับการเรียน จึงใช้ตัวเลขหลายค่ามาแทนเวกเตอร์ใบหน้า

ตอนลงทะเบียนจะเก็บเวกเตอร์เป็น JSON ส่วนตอนเช็กชื่อจะส่งเวกเตอร์อีกชุดเข้ามา ระบบคำนวณ Euclidean Distance ระหว่างสองชุด ถ้าค่าไม่เกิน `0.6` ก็ให้ผ่าน

ดังนั้น `face_embedding` ใน `models.py` จึงเป็นเพียงช่องสำหรับเก็บข้อมูลเวกเตอร์ ไม่ได้หมายความว่าเป็น embedding 128 มิติจากโมเดลสำเร็จรูป

## 3. ลำดับการเช็กชื่อ

การทำงานหลักอยู่ใน `AttendanceService.evaluate_checkin()`

1. เช็กก่อนว่ารอบยังเปิดอยู่และยังไม่หมดเวลา
2. คำนวณระยะ GPS
3. ถ้าไกลเกิน 50 เมตรให้หยุดและแจ้งว่าอยู่นอกระยะ
4. ถ้าระยะผ่าน จึงไปเทียบเวกเตอร์ใบหน้า
5. ถ้าผ่านทั้งสามขั้นตอนจึงส่งผลว่าเช็กชื่อสำเร็จ

การตรวจทีละขั้นทำให้รู้ด้วยว่าถ้าไม่ผ่าน เกิดจากเวลา ตำแหน่ง หรือใบหน้า

## 4. การเก็บข้อมูล

ตอนนี้โปรเจกต์ใช้ `src/store.py` เป็นตัวเก็บข้อมูลแบบง่าย ๆ ในหน่วยความจำ เพื่อให้ทดลองระบบได้โดยไม่ต้องตั้งฐานข้อมูลก่อน

ข้อเสียคือข้อมูลจะหายเมื่อปิดโปรแกรม ซึ่งเป็นข้อจำกัดของเวอร์ชันนี้

## 5. โครงสร้างโดยรวม

```text
templates/       หน้าเว็บ
static/          JavaScript และ CSS
src/app.py       API และการเชื่อมหน้าเว็บกับระบบ
src/store.py     ข้อมูลตัวอย่างที่เก็บในหน่วยความจำ
src/attendance_service.py  กฎการเช็กชื่อ
src/models.py    ตัวอย่างโครงสร้างตารางสำหรับต่อยอดเป็นฐานข้อมูล
 tests/          โปรแกรมทดสอบ
```
