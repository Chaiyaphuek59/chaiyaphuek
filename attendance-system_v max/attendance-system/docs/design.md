# แนวทางการออกแบบระบบ

เอกสารนี้อธิบายส่วนที่สำคัญของระบบตามที่ทำไว้ในโปรเจกต์ปัจจุบัน

## 1. การคำนวณระยะ GPS

ระบบต้องเปรียบเทียบตำแหน่งของอาจารย์กับตำแหน่งของนักศึกษา จึงใช้สูตร Haversine เพื่อประมาณระยะห่างระหว่างพิกัดละติจูดและลองจิจูด

ในโค้ดกำหนดระยะสูงสุดไว้ที่ 50 เมตร

```text
ระยะ <= 50 เมตร  -> ผ่าน
ระยะ > 50 เมตร   -> ไม่ผ่าน
```

ค่า `6371000` ที่อยู่ในฟังก์ชันคือรัศมีโลกโดยประมาณในหน่วยเมตร

## 2. การตรวจสอบใบหน้าในโปรเจกต์นี้

ส่วนนี้เป็น **การจำลองการตรวจสอบใบหน้า** เพื่อให้เว็บสามารถทดลองขั้นตอนการเช็กชื่อได้ โดยหน้าเว็บจะนำข้อมูลภาพจากกล้องมาทำเป็น vector แบบง่าย แล้วส่งไปที่เซิร์ฟเวอร์

เซิร์ฟเวอร์จะเปรียบเทียบ vector ที่ลงทะเบียนไว้กับ vector ตอนเช็กชื่อด้วย Euclidean Distance

```text
ระยะของ vector <= 0.6 -> ถือว่าตรงกัน
ระยะของ vector > 0.6  -> ไม่ตรงกัน
```

ไม่ได้หมายความว่า vector นี้เป็น face embedding 128 มิติจากโมเดล Face Recognition จริง หากนำไปพัฒนาต่อควรเปลี่ยนส่วนนี้เป็นโมเดลรู้จำใบหน้าที่เหมาะสม และจัดการข้อมูลชีวมิติอย่างระมัดระวัง

## 3. การจัดการข้อมูล

ตอนนี้โปรเจกต์ใช้ `src/store.py` เก็บข้อมูลในหน่วยความจำ เพื่อให้ทดลองระบบได้ง่ายโดยไม่ต้องติดตั้งฐานข้อมูลเพิ่ม

ข้อเสียคือเมื่อรีสตาร์ตเซิร์ฟเวอร์ ข้อมูลนักศึกษา ชั้นเรียน รอบเช็กชื่อ และประวัติที่สร้างขึ้นระหว่างรันจะหายไป

ใน `src/models.py` มีโครงสร้าง SQLAlchemy ที่เตรียมไว้สำหรับแนวทางการใช้ฐานข้อมูลในอนาคต แต่เวอร์ชันที่ส่งนี้ยังไม่ได้เชื่อมกับฐานข้อมูลจริง

## 4. ลำดับการเช็กชื่อ

1. นักศึกษาเข้าสู่ระบบ
2. อาจารย์เปิดรอบเช็กชื่อและส่งตำแหน่ง GPS ของตัวเอง
3. นักศึกษาเปิดหน้าชั้นเรียน
4. เว็บขอตำแหน่ง GPS และข้อมูลจากกล้อง
5. ส่งข้อมูลไปยัง API เช็กชื่อ
6. ตรวจสอบเวลา
7. ตรวจสอบระยะ GPS
8. ตรวจสอบ face vector
9. ถ้าผ่านทั้งหมดจึงบันทึกผลการเข้าเรียน

## 5. สิ่งที่ยังไม่ได้ทำในเวอร์ชันนี้

- ยังไม่มี face recognition model จริง
- ยังไม่มีฐานข้อมูลถาวร
- ยังไม่มี audit log สำหรับทุกการเปลี่ยนแปลง
- ยังไม่มีระบบ reset password แบบเต็ม
- ยังไม่ได้ออกแบบระบบสำหรับการใช้งานจริงในปริมาณผู้ใช้จำนวนมาก
